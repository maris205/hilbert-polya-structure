# Hostile audit

Release-blocking failure modes include: wrong Coriolis sign; missing collinear interval; treating sampled roots as an existence proof; checking only L4 or one sign of `Omega_xy`; using the triangular characteristic roots without proving all four `L4/L5` and `lambda=plus_or_minus i/sqrt(2)` critical ranks; calling `mu=mu_R` stable; falsely excluding resonant masses from open-chamber linear boundedness; including collisions; extending five isolated points to `mu=0`; or promoting linear boundedness to nonlinear resonance/KAM stability.

The mutation lane recomputes hashes after semantic and structural changes and attacks complete theorem/proof/Route contracts, source tokens, rows, grids, and each of the four critical rank cells.  Exact-type attacks set false booleans to integer zero, true booleans to integer one, and multiplicities/counts to booleans.  Raw duplicate JSON keys and a stale-hash control are separately rejected.  A dedicated YAML lane rejects repaired semantic changes, missing and unknown keys, boolean--integer substitutions, duplicate top and nested keys, and anchor/alias/merge carriers.  The checker imports no producer module.

Release status is determined by `python3 code/c290_release_manifest.py`.
