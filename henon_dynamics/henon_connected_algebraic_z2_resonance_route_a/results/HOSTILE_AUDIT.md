# Hostile semantic and release-entry audit

Population: 25 repaired-payload-hash mutations, four direct YAML attacks,
and the same four YAML attacks through the actual release --write entry.
There are 33 attacks, not 33 different mathematical perturbations. The
executed result was rejection of 33/33, including all four real write-entry
attacks at the specified evaluation gate.

The 25 evidence mutations cover an unknown root key; true and integer-zero
scope flags; a boolean epoch; source drift; tuple promotion; omitted and
reordered rows; boolean HNF entries; integer and boolean matrix entries;
corrupted left and right unimodular witnesses; Smith factors; characteristic
coefficients; suppressed resonance; wrong nullity; replacement of components
by the pseudodeterminant; an unsaturated Gram matrix; a wrong Gram determinant;
torus census and cycle entries; Dirichlet sum and tail; and a summary count.
Every payload hash is repaired before the independent checker is invoked.

The four YAML attacks add an unknown field, replace false by integer zero,
remove the date quotes, and add a duplicate candidate identifier. Direct
evaluation checks reject all four. The integration attacks copy the package
and evaluator authority to a fresh repository-shaped temporary directory.
They invoke its real release script with --write and require a nonzero exit
specifically reporting the evaluation raw-hash gate, not merely a missing
file, authority error or compile failure. No original package file is changed.

Unknown-field and type drift cannot be legitimized by manifest write mode.
The evaluation also uses a duplicate-key rejecting parser and a canonical
parsed-data/type hash in addition to the frozen raw-byte hash. Optimized
execution is a separate twelve-case refusal population in the release lane.

The manifest contains the actual final attack receipt. These tests probe
declared failure modes and do not claim exhaustive adversarial coverage.
