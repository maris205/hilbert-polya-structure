# 研究与交付工作流

这是当前执行流程；`AGENTS.md` 提供工作区约定，批次接续文件只记录状态。历史提案、评分表、冻结脚本不构成另一套通用启动流程。

## 从当前工作接续

读取最新用户要求和当前批次接续文件，确认目标、已完成项、下一项缺口、具体输入与验收条件。只读取该阶段所需资料；通过索引或定向搜索定位历史证据。继续已确认动作，不因旧快照中的“待确认”重复停下。

任务决定动作范围：回答/审查交付结论；诊断定位原因；实施/修复执行改动及必要验证；监控使用现有等待机制。不要把只读评价自动扩张为实验、登记册写入或外部操作。

## 每篇论文

1. **选择问题。** 从上一项真实结果选族内有价值、与已有论文不碰撞的问题。查新使用当前相关一手来源，记录引用和仍不确定的结论。新想法先验证价值再创建完整项目，不为凑数拆文章。
2. **建立论证。** 明确对象、假设、结论和边界；完成证明或所需实验。实验才需要相应数据划分、预算和冻结参数；纯证明论文不补造数值项目。按可独立验证的部分并行分工。
3. **审查内容。** 独立审查关键证明、反例和结论边界；修正真实问题，遵守项目已约定的审查要求。已经通过且未改变的论证不因后续排版或依赖缺项重新审查。
4. **制作产物。** 按当前项目锁定的署名、正文页数、参考文献、构建依赖和 PDF 标准编译。记录实际执行和结果；输出路径遵循验收记录，不强行改名为 `paper/paper.pdf`。普通新项目采用足以复现的简单构建；已有受约束项目沿用其已确认构建边界。
5. **验收与接续。** 完成实际 PDF、必要可复现性和独立终审，更新一次当前状态并链接接受的产物。下一篇由上一篇的实际结论决定。五篇实质完成后统一做跨论文审查并暂停；失败/阻塞状态不计作完成篇数。

## 评价路由与记录

- 明确提出算术动力系统、Riemann 动力行列式主张时使用 Route A。纯 Hamiltonian 结构或编译任务不强制评分；需要说明适用性时写 `route_applicability: NOT_APPLICABLE`，它不是科学失败或 Route PASS。
- Route B 正式评价需要 Route A 就绪；用户要求的有限早期算子审查只回答该问题，缺失域等记为开放义务，不授予层级 PASS。
- 评分细则、枚举与 YAML 格式按对应 `SKILL.md` 的参考文件读取。正式报告继续兼容原版本；非 Git 工作区的 commit 字段用 `null` 并说明原因，以相关文件哈希或现有清单绑定输入。
- 一般科学记录可用 `PROVED`、`CONDITIONAL_THEOREM`、`NUMERICALLY_CERTIFIED`、`NUMERICAL_OBSERVATION`、`HEURISTIC`、`CONJECTURE`、`MODELING_CHOICE`、`FITTED_PARAMETER`、`OPEN`、`REFUTED`。正式 v0.2.0 评价的 `evidence_status` 仍按对应 rubric 枚举，猜想可在说明字段注明。Route 评价另用各自枚举；`NOT_TESTABLE` / `STOP_SCOPED` 表示可评估性或范围处置；产物是否通过单独陈述。历史报告不追溯改标签。
- 持久化新的正式评价时保存新版本；只有新候选结论、真实 obstruction 或算子义务才更新对应登记册。没有新证据就不制造重复审查或状态条目。

## 失败恢复

先保留实际错误、输入身份和已运行步骤，区分已知原因与推测。选择能解决原因的最小修正，在已有权限和资源范围内推进并做针对性验证；一次失败不自动意味着再次询问用户。

对于已冻结、已耗用的单次实验或专门约束的构建，只按该项目已获准的 successor 方案执行；使用新版本/新根，不修改原失败或擅自重跑。只有新问题超出确认范围、需要新资源或改变验收标准时提出具体决策。不要反复测试同一失败且不改变其原因。

本地论文编译通常不需要另建分布式 exactly-once/release 服务。若特定任务确需此类保证，应单独论证必要性和范围；它不是论文质量的默认条件。

## 模型与技能维护

当前提示优化目标是 GPT-6 Astra：常驻规则保持短小，技能按任务加载，独立任务积极并行，验证随变更而定。保留现有有效推理强度，不将所有子任务统一强制为最高档；说明文件本身不会切换运行中的模型。
