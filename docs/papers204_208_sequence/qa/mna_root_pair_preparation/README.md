# MNA root fresh-pair preparation

Source-only infrastructure prepared for root's independent original inspection
and later execution. This preparation is not an executed replay, a mathematical
or manuscript review, admission, or future PASS. The preparer worked on other
documentary infrastructure; candidate-assessor/author familiarity grants no
review credit. Root retains proof/source judgment and the admission decision.

Only `run_pair.py child 01` and `child 02`, invoked by the root runner later,
compile and execute scientific bytes. The scientific source is copied exactly
from the sealed independent `MNA_GATE/verify.py`; it is never patched or imported
from another scientific implementation. Its cutoff remains the original complete
N=1..12, 4,095 states, 115,680 checks per run. Neither a new literal nor a larger
experiment is available through this interface.

The previous gate pair used Conda Python 3.12. This root pair deliberately uses
`/usr/bin/python3.10` with `-I -S -B`, optimization zero, the exact four-variable
sanitized environment, and separately named absent cache prefixes for parent and
each child. Existing/dangling cache paths, import ZIP and interpreter override
files are rejected. All 997 original dependency keys are retained exactly, with
their original expected hashes/sizes checked before and after. The complete
309-payload gate plus its manifest is rechecked, not rewritten.

Added inputs comprise the system interpreter/stdlib sources and extensions,
declared shared-library superset, loader/Bash/environment tools, complete locale
and gconv resources, relevant configuration/absence states, preparation sources
and two exact execution-source copies. These are recorded before and after;
resolved names supplement, never replace, original names. Full resource and
configuration membership is compared. Only the runner and verifier are physically
copied; existing runtime trees and scientific evidence are not duplicated.

The runner records parent and both child early/late module/map samples, full raw
volatile maps, and Python open events during verifier source execution. Every
observed ordinary file must be covered by the before capsule. Nonfile Python-open
paths are accepted only as absent probes beneath the assigned child cache prefix;
unexpected volatile opens or disappeared ordinary paths fail closed. Hooks start after
instrumentation imports; this is explicitly not exhaustive OS, startup, or
continuous tracing. No `strace` execution is claimed. Initial imports are covered
by module/map samples and the declared input superset, not retroactive open events.

Future execution writes only the new
`qa/root_replays/mna_gate_pair_01/` directory. Every native child receives a
pre-spawn attempt record, full stdout/stderr, exact argv/cwd/environment, timeout
and actual exit record. A spawn failure has null native exit and empty native
streams; a timeout has null unobserved returncode and explicitly partial streams.
Their synthetic wrapper codes and exception diagnostics are separate fields.
Two full raw stdout streams are compared to the preserved
canonical and to each other using native `cmp`; two additional source comparisons
and before/after `ldd` closure are captured. Caught execution/closure failures retain
output and attempt a failed package seal; entry failures or a sealing failure may
leave only partial evidence. Nothing is overwritten and the directory is never
reused. `RESULT.json` reports execution/input checks before sealing, so root must
require the successful parent native exit and verified full seal as well. The parent entry record is honestly
labelled entered-process evidence, not its own pre-spawn receipt. Root must retain
the parent tool invocation, complete streams and actual exit separately.
