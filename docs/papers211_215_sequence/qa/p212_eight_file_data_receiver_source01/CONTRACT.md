## Separate authority and provenance

Later a separately source-received fixed-document loader may deliver complete
Buffers and independently authenticated context pin. No loader is implemented
or authorized here. Its ordinary Node/fs/crypto, parser, bootstrap and trusted
ancestors may be adopted explicitly; no recursive self-observer is proposed.
This receiver does not pretend that a manifest can authenticate its own pin.
The context pin MUST come from actual separate root reception, not from the
context or captured envelope. Root must authenticate every original native
request/return and its exact parsed projection, complete source-copy keys,
binding before/after keys, actual grant/consumption and complete settled raw
keys BEFORE trusting this context. Raw originals may be tool-rendered text,
so the receiver retains/pins their entire bytes but does not parse an invented
universal native-original format. The authenticated projection is an explicit
trust interface, not a claimed new independent original/projection check.
The receipt reference and grant assertions have no authority by themselves.

Each full closed-document key has exact path, four complete ten-field stat
objects, bytes_read, explicit EOF, successful close and complete content pin.
All four metadata structures must agree; size and read bytes agree with the
whole supplied body. Source roles/destinations and two original source pins
are fixed in source. Binding and grant bytes/pins are actual later inputs,
never invented expected values. stdout/stderr refer to distinct single-link
literal captured files. The adapter must disclose archive-copy mappings
separately if it reads archival copies; literal original provenance must not
be silently relabelled as the archive file's physical key.

## Complete DATA grammar and failure handling

Whole stdout is at most 268435456 bytes; separate stderr intake at most
8388608 bytes. The latter is an intake limit, NOT a global native-bootstrap
stderr production guarantee. Over-limit, absent, malformed or truncated data
is unaccepted and retained as supplied; no suffix is invented. Parsing and
reencoding require ordinary available memory and CPU, not a hard resource
guarantee. Every code unit excluded by the original serializer is lower-case
UTF-16 `\uXXXX`; lone surrogates are not normalized. Default JavaScript key
sort uses UTF-16 order. Arrays must be dense; numeric values safe integers
excluding negative zero; at most 8192 value nodes/depth32. Whole ASCII
canonical reencoding, including exactly final LF, must RAW-equal stdout.
Duplicate keys, alternative escape spelling, whitespace and unsafe numeric
encodings therefore cannot receive canonical acceptance.

Every request_input field is checked against its fixed grammar, with all
available partial stats/errors/close state/body retained. Complete request
body must RAW-equal the external whole binding and each complete stat must
equal its external before key. Partial failure bytes must be its literal
prefix. Bound request permits only the accepted activation/status/grant delta;
all eight candidate definitions, limits, purpose, expected-null values,
settlement-null and role order are fixed. Reader rows are complete exact-key
records. Present success requires all four ten-field stats, same metadata,
regular file, fd, actual zero-EOF flag, close, body length/size/SHA equality.
Optional ENOENT is accepted only in the exact absence row grammar and only
for the final two optional entries, with no invented metadata or content.
Partial failure rows are retained with available metadata, errors, close
errors and all body hex; they are not claimed successful file keys. Their
body's SHA is recomputed for every row, including failed/absent rows, and
returned in body_pins; it is additionally compared whenever reader content
exists. The reader intentionally has content=null for read-loop failure.
Retained bytes remain bounded by one
possible overflow sentinel. Accepted-byte census excludes the failed row;
row census/present/absent/failure totals are reconstructed. Missing unreturned
reader rows remain unknown, even when reader_called=true.

Native context has all initial/continuation frames plus entire original
request/return bytes and pins. Exact initial command/arguments and only empty
same-session write_stdin continuations are permitted; no retry/kill/new launch.
Actual final exit and absence of live session are required. Nonempty native
control output conservatively yields HOLD with all raw bytes retained. An
initially final request has no session and zero continuations. Zero requires
successful eight-row envelope and empty separate stderr. Returned reader
failure maps to78; entry failure to79; a later entry/close failure may leave
a complete envelope with native79. No observational failure is upgraded to
success. Generic diagnostics remain whole separate raw DATA, not execution
instructions or proof that stdout is complete.

Success means RECEIVED_EIGHT_FILE_DATA_ONLY under authenticated external
provenance, never source acceptance, installed closure, operation permission,
dependency interpretation, manuscript acceptance, or completion of P212.
