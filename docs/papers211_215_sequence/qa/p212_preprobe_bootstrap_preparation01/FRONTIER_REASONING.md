# Why these finite paths, and what is not yet known

Every allowed spelling is literal in FRONTIER.json. Its origin labels describe
how the spelling was chosen, not whether the host currently contains it.
All existing archive path/size/hash observations remain historical only.

## Received documentary bases

The old root runtime source/discovery receptions and their actual complete
receiver body establish the earlier read/key mechanism and its limits. The
complete original Python RUNTIME_LOCK.json, its complete outer-probe raw JSON,
Node NODE_RUNTIME_LOCK02.json and NODE_PROBE04.json were actually read as
archived data. Their saved source/config/loader and import records were parsed
as JSON, never imported or executed. Full stored native read results are in
ARCHIVAL_READS_NATIVE.json. SOURCE_INPUTS.sha256 pins these repository documents,
not the current host paths mentioned inside them.

The old Python outer sample reports Python 3.10.12 and the three archived
sys.path spellings /usr/lib/python310.zip, /usr/lib/python3.10 and its
lib-dynload subdirectory. The old Node sample reports 22.22.2 and four initial
builtin imports. These version strings choose documentary reference tags;
they do not assert current installed versions or current binary-source equality.

## Interpreter and import frontier

Bash /bin/bash and its recorded /usr/bin/bash resolution, /usr/bin/env,
Python /usr/bin/python3.10 and Node /usr/bin/node are whole-file candidate
roles. Explicit /bin, /lib, /lib64, /usr/lib64 and all ancestor components
permit only bounded alias observations; their current link texts are unknown.

Forty Python source candidates are the archived subset associated with the
probe's os/stat/signal/hashlib/json/subprocess/traceback and shared encoding,
collection, regular-expression, threading and tokenization families. This
is a bounded shared-import candidate set, not an assertion that every listed
file must load or that it is already a complete transitive proof.

New ctypes/__init__.py, ctypes/_endian.py and struct.py are source-derived
candidates. CPython's tagged ctypes source directly depends on _ctypes, struct,
os/sys/types and later ctypes._endian; struct.py depends on _struct. The
_endian module refers back to ctypes and sys. These primary sources justify
the named frontier, not the installed files' equality to upstream.
[ctypes source](https://raw.githubusercontent.com/python/cpython/v3.10.12/Lib/ctypes/__init__.py),
[endian source](https://raw.githubusercontent.com/python/cpython/v3.10.12/Lib/ctypes/_endian.py),
[struct source](https://raw.githubusercontent.com/python/cpython/v3.10.12/Lib/struct.py).

The new _ctypes extension spelling uses the archived CPython 3.10 x86-64 ABI
suffix and is explicitly UNOBSERVED. The possible _struct extension is optional:
an absent .so does not prove a builtin implementation. Whole _ctypes ELF bytes
are requested for later static dependency reasoning. Exact libffi DT_NEEDED,
its versioned leaf, loader lookup alternatives and every alias are unavailable
until those actual bytes/configurations are received. This packet deliberately
does not invent libffi.so.8.1.0, read a library-directory glob, or call ldd.

The old _hashlib/_json extension paths, interpreter shared-map candidates,
libcrypto, expat, zlib, libc/libm and Bash's libtinfo roles are retained as finite
candidates with their recorded aliases/referents. Node's archived executable
and shared objects, including pthread, gcc_s, stdc++ and dl, are similarly
whole-file candidates. _decimal/libmpdec, fractions, decimal, datetime,
argparse/gettext, pathlib/urllib, scientific helpers, cmp, diff, ldd and dash
are NOT copied wholesale into this author-probe frontier.

Actual selected source bodies must still classify normal and exceptional
imports, frozen/builtin modules, suffix choices, import alternatives, zip/
pyvenv/_pth and bytecode behavior. The fixed future cache must remain absent.
Any missed source-driven candidate stays HOLD until a separately received
finite amendment; enumeration after an author import is too late to authorize it.

## Configuration and memberships

The initial loader candidates are ld.so.cache/conf and the complete archived
22 named conf.d bodies and one-level name guard. OpenSSL configuration aliases,
locale defaults/aliases, timezone, locale-archive state, C.utf8 data and
gconv configuration/cache files are explicit. Five one-level directory name
sets are copied as literal guards, including the 256-name gconv set; this
does not approve unselected conversion libraries or assert that all names
affect this exact probe. Their relevance remains source follow-through.

The nine archived loader directory spellings and explicit recorded resolutions
are metadata identities, not directory membership claims. Null membership
means not observed by this operation, never empty or irrelevant. Changed
configuration includes or lookup destinations cannot cause an automatic
directory walk or new body read.

Node's relocated .js sources require a fresh package.json ancestry: eight
literal paths from the exact new source directory up through /package.json.
The two old package directories are not reused. No NODE_OPTIONS loader or
preload is in the selected Node probe prefix. Its six explicit builtin names
are fs, path, crypto, child_process, assert/strict and module. The old four-name
probe is not source evidence for all new lazy/native bindings; the complete
current binary/source registry and finite source-derived lazy policy remain
separate open work.

BASH_ENV, exported shell functions, inherited LD_* and unrelated user shell/
account files are not sampled as a purported product-startup attestation.
The trust boundary explicitly leaves those inherited effects unmeasured.
No /etc/passwd, /etc/group, parent environment or parent /proc dump is added.

## Names, metadata and absence are different evidence

164 target rows and 204 component permissions do not imply 204 complete file
bodies or an exhaustive closure. Ancestors are explicitly identified by path
and receive their own native lstat records during componentwise traversal.
The observed lexical lstat, final referent stat and every intervening link
text remain distinguishable. Unexpected link referents are not dereferenced.

The sole required absent target is the root-selected author Python cache.
Optional states are captured as actual absence or complete bounded file bytes/
directory identity, then must be semantically classified by root. Absence is
supported only by actual ENOENT, or by an observed non-directory component
plus actual ENOTDIR; permission/I/O errors are failures, not absent files.
