# Symbolic Dynamics research workflow

Active procedure, 2026-09-05. Read this for research execution, not every
status question. Batch-specific contracts and accepted evidence retain their
scope; historical evaluation schemas remain unchanged.

## Recover and choose the next obligation

`SYMBOLIC_DYNAMICS_STATE.md` identifies the batch; its `PIPELINE_STATE.md`
identifies the milestone, remaining work and controlling evidence. Read the
relevant original before using a claim. Retrieve history by literal update,
conjugacy/factor map and proof mechanism, rather than loading every old log.
Read selected instruction files completely; search evidence files narrowly.

For a continuation, finish the active batch. For a requested next round after
completion, start five fresh seats with numbering after the recorded maximum.
A report/review request remains read-only unless changes are also requested.
Keep the original HP arithmetic program distinct from the current broad
finite-system track. Neither a short-paper stage nor an internal PASS opens
Route B or establishes global novelty.

## Research gates

1. **Scout and reject early.** Define the literal finite autonomous map and
   use small exact pilots to seek a rigid temporal/recurrent structure plus
   a separate inverse, fibre, enumeration or extremal mechanism. Check old
   papers, killed scouts and direct primary sources. Deduct known primitives,
   conjugates, factors and standard proof mechanisms. Weak signals trigger a
   different system, not an automatic larger cutoff. Reserves are not papers.
2. **Admit and write.** Freeze a bounded theorem contract only after its
   all-parameter proof routes and source/collision checks survive the candidate
   gate. Write a self-contained anonymous short paper with an explicit advance,
   limitations, paper-local verifier and full canonical output. Finite checks
   pressure proofs; they cannot establish an all-size theorem. Freeze Round0.
3. **Review and repair.** Obtain two actual process-separated manuscript
   reviews. A works from Round0; accept its exact repaired or no-change delta
   before freezing Round1. B works from pinned Round1 using a materially
   different representation/proof route, then accepts a delta before Round2.
   Authors, including proof contributors, cannot review their own paper.
   Preserve input pins, independent verifier/canonical, proof/source/build
   records, finding census, deltas and complete nonself manifests. Root checks
   the original evidence and performs the required successful replays.
4. **Complete and synchronize.** Each retained paper needs zero current open
   findings, both accepted rounds, two physical source-only terminal builds,
   actual viewing of every final page and complete artifact checks. Run the
   batch's full terminal gate before declaring exactly five papers complete.
   Preserve rejected numbered drafts and explicitly unresolved historical
   caveats. Refresh batch/root state and synchronize scoped work to private Git.

The P197–P203 implementation contract is in the completed batch's
`PROBLEM_ANCHOR.md`, `STANDING_WORKFLOW_AUTHORIZATION.md` and
`HOSTILE_REVIEW_PROTOCOL.md`. New batches may reference this procedure and
record only their specific scope, contracts and departures; do not duplicate
generic instructions across every paper. A failed admission reopens the seat.
Unresolved proof or evidence defects never become PASS to meet a quota.

## Verification follows the changed dependency

| Change / event | Required verification |
|---|---|
| New theorem, map, proof or verifier | Affected mathematical checks, source/owner review and review/delta gates; finish the contractual terminal gate before completion |
| Revised manuscript, bibliography or PDF | Affected claims/citations, reviewer delta and source-only builds; actually view all changed final PDF pages, and all pages for terminal acceptance |
| First full-batch completion | All five contracts; required exact author/A/B replay pairs, ten terminal cold builds, complete page views and manifest closure |
| Lifecycle text, index or instruction edit only | Check links, scope, changed manifests and unchanged scientific pins; prior valid mathematical/build/view evidence remains valid |
| New failure, dependency change or unresolved concern | Reopen and verify its affected scope; broaden only when the evidence warrants it |

Record command, exit status, inputs, complete stdout and canonical comparison
for a replay. If calling a comparison byte-exact, compare raw bytes; normalized
text equality is a different claim. Distinguish a new execution from checking
archived evidence. A PNG's existence/hash is not a visual review. Hash-only
refresh is valid only with a prior passing gate and unchanged scientific
dependencies; it is never labelled a fresh numerical or visual test.

The reuse key covers imported code, data, parameters, canonical output and
relevant runtime settings, not just the main script. Build evidence also
depends on TeX/bibliography/resources/styles and engine configuration.
Incomplete provenance or a changed dependency requires fresh affected checks.

Use existing batch auditors for their documented layouts. In particular,
package manifests are directory-relative while review input pins may be
workspace-root-relative. Do not relax parsers or overwrite frozen receipts
to make a new layout pass: add a scoped, disclosed adapter when necessary.
For a new batch, agree verifier/canonical/report/delta/pin roles and the
auditor's expected layout before generating review packages. Keep intake
notes separate from final verdicts and avoid empty template-only artifacts.

## Parallel work, recovery and Git

Parallelize useful independent work while keeping a local task moving.
Give each agent a question, input paths, output ownership and acceptance
criterion. Avoid concurrent edits to the same paper or central indexes;
root integrates and verifies claims. Candidate familiarity and reused code
are disclosed; process separation is not blind or external expert review.

Checkpoint decisions and evidence at milestones, not after every tool call.
Keep raw logs in artifacts and return compact results with paths to the main
thread. Change-sensitive verification does not waive required paper gates.

Resolve the mirror from `HISTORY_AND_CAVEATS.md`; inspect its current status
and exact path mapping before copying or staging. Synchronize only owned
changes, preserve unrelated work and verify the actual pushed ref. If the
remote advanced, inspect overlap before a normal merge; never force-push or
rewrite history. Record the actual commit after it exists, without a circular
self-hash claim. Private synchronization is covered by standing authorization;
external manuscript upload, submission, publication and contact remain held.
