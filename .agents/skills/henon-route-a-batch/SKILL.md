# Hénon Route-A batch

Deliver five complete, independently meaningful papers under the current user
contract. Favor mathematical progress and informative elimination of a model
class over artifact volume or small variations of a known result.

## Entry and routing

1. Read `henon_dynamics/CURRENT_RESEARCH_STATE.md` from the repository root;
   verify the referenced Git/artifact state and newest user instruction.
2. Read [WORKFLOW.md](references/WORKFLOW.md) completely for batch work.
   Resume the first unfinished gate; do not restart accepted work merely
   because the session, model, or calendar date changed.
3. Read the chosen evaluator in full when making an evaluation. The established
   C-series authority is `flow_systems/skills/route-a-evaluator.md` v0.2.0.
   Resolve its prior-work paths within `flow_systems/`, and also inspect relevant
   Hénon collision/obstruction records. Preserve recorded version hashes.

## Decisions, not ceremony

- Freeze the mathematical object and one substantial paper-level question
  before expensive implementation. Specify success, a decisive counterexample,
  and the boundary that would trigger model replacement.
- Use the current team's selected model; no mandatory GPT-5.4 reviewer, external
  MCP server, paid API call, GPU pilot, or fixed number of rewrite rounds.
  Distinguish available tools from examples in other skills.
- Parallelize independent papers or independent proof checks with disjoint
  write ownership. Review the actual theorem and evidence, not a favorable
  summary supplied by its author. Label current-team review as internal.
- Keep the user-authorized five-paper checkpoint. Broad subtype exploration
  overrides the evaluator's generic stay-in-one-family example for this task;
  it does not alter any scientific grade, required control, or evidence label.
- If another applicable skill is required by the session, follow its relevant
  instructions and disclose conflicts with the user's contract. This skill
  does not disable session-level skill requirements or edit installed plugins.

Finish with linked PDFs, each paper's actual increment and route verdict,
verification results, Git status, and the next user checkpoint. Do not promise
novelty, publication readiness, model speedups, or target success without evidence.
