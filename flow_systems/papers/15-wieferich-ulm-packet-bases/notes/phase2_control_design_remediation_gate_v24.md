#### 8.6.4 Semantic reconstruction rule

For each SNAP independently, the reducer starts from the complete raw STAT,
FD_DIR, B_FDINFO, identity-status, and cgroup reads. It validates the exact
terminal grammars, parses semantic integers/tokens/raw paths, verifies parent
and frozen-object joins, derives controller and cgroup order, derives the
fdinfo/B1/CLOEXEC relation, and then reconstructs every terminal leaf. It
then constructs every nested TOKEN, FIELD, SEQ, entry, projection, bracket,
and ten-FIELD observation from those semantic values.

A caller-supplied `canonical` tag, pre-encoded relative component, pre-sorted
controller/cgroup list, `parsed_fdinfo_flags`, cached projection, declared
length/count, or digest is never an input authority. Source bytes that parse
to the same semantic value but differ from the sole grammar are rejected,
not normalized. Only after both SNAPs have been independently rebuilt does
the direct byte-equality reducer run.

~~~text
U16BE(x)=exactly two unsigned big-endian bytes
U64BE(x)=exactly eight unsigned big-endian bytes
BOOL(false)=0x00
BOOL(true)=0x01
TOKEN(s)=ASCII(s), where s is one exact closed-enum token

FIELD(tag,value)=
  U16BE(byte_length(ASCII(tag)))
  || ASCII(tag)
  || U64BE(byte_length(value))
  || value

SEQ(item_tag,item_1,...,item_n)=
  U64BE(n)
  || FIELD(item_tag,item_1)
  || ...
  || FIELD(item_tag,item_n)
~~~

`FIELD` and `SEQ` are recursive: every structured value is the exact
concatenation of the named FIELDs below; every variable-cardinality list is
one SEQ with its exact count. There is no padding, alignment, native-endian
integer, NUL terminator, implicit delimiter, unknown field, omitted field,
alternate tag spelling, duplicate tag, or trailing byte.
