## 4. Canonical scalar and byte grammar

Every CSV row uses the literal schema value
`paper15r-wieferich-ulm-controls/1`.  The manifest schema is
`paper15r-wieferich-ulm-controls-manifest/1`.

### 4.1 Scalars

- Integers are base-ten ASCII, with no leading `+` or leading zero except
  `0`.  Negative integers use one leading `-`.
- Booleans are exactly `true` or `false`.
- An absent optional value is the empty field, never `NA`, `null`, `None`,
  or whitespace.
- A finite integer vector is `[a;b;...]`, with no spaces.  The empty vector
  is `[]`.
- A matrix is a row-major vector with rows separated by `/`, for example
  `[0;1]/[1;0]`.
- A factorization lists increasing prime factors as `q` or `q^e`, joined by
  `*`; exponent `1` is omitted.  The factorization of `1` is `1`.
- A relative path uses `/`, contains no `.` or `..` component, and is never
  absolute.
- A SHA-256 value is exactly 64 lowercase hexadecimal characters.
- `case_kind` is one of `DIAGNOSTIC`, `RECEIPT`, `NEGATIVE`, `SUMMARY`.
- `mutation_id` is empty off negative rows and is exactly `S01` through
  `S35` on the registered semantic-negative rows.
- `negative_reason` is empty off negative rows and exactly one registered
  token on a negative row.
- `status` is the literal `PASS` only after the subject has produced the row;
  the verifier ignores that field until it has recomputed the row.
- Every present `tolerance` is `0`.  Floats, decimal approximations, `NaN`,
  infinities, scientific notation, or a nonzero tolerance are invalid.

### 4.2 CSV and JSON bytes

All CSVs are UTF-8 without BOM, use LF, and use the Python standard-library
writer contract

```text
delimiter=",", quotechar='"', quoting=csv.QUOTE_MINIMAL,
doublequote=true, escapechar=None, lineterminator="\n"
```

with files opened using `newline=""`.  Headers and row order are exact.
There is no leading/trailing field whitespace and exactly one terminal LF.

The manifest is

encoded as UTF-8 without BOM.  Absolute paths, timestamps, host names,

Every manifest `bytes` value is the exact octet length of the corresponding
on-disk file, and every digest is SHA-256 over those same complete bytes.

## 5. Independent subject/oracle split

`code/generate_controls.py` is the subject.  `code/test_controls.py` is the
independent oracle.  The oracle must not import the generator, a shared
helper, or a generated Python object.  It invokes the generator only as a
subprocess when generation is required, then parses bytes independently.

The two sides use deliberately different methods:

| Surface | Subject method | Independent oracle method |
|---|---|---|
| valuation/factorization | repeated division of the directly computed integer | trial division producing a fresh canonical factorization, followed by multiplication back to the integer |
| multiplicative order | repeated modular multiplication until `1` | factor `ell-1`, reduce a candidate order by prime divisors using modular exponentiation, then verify minimality |
| finite kernels | image-order/gcd and deterministic elimination | exhaustive enumeration of every element of the frozen small source group |
| truncated heights | multiply the subject kernel representation | enumerate the oracle kernel afresh, multiply every element, and compare sets |
| signature prefix | subject valuation routine | oracle recomputation directly from the hard-coded primitive `(p,r)` registry, never from copied `kappa` values |
| basis swaps | determinant/unit calculation | enumerate the finite block and verify bijection, element orders, and group law |
| file bindings | subject SHA-256 pass | a separate oracle byte read and SHA-256 pass over the exact path registry |
| manifest totals | subject counters | recomputation from parsed CSVs and filesystem inventory |

The oracle carries its own hard-coded primitive fixture and mutation
registries.  It does not hard-code derived valuation, order, kernel, height,
or summary answers.  For a negative test, the expected detector comes from
the test-method registry, not the mutated row's `mutation_id`,
`negative_reason`, `oracle`, or `status` fields.  Changing those four fields
cannot make an invalid fixture pass.

## 12. Reproduction, verify-only, concurrency, and cleanup contract

The only future top-level entry is `experiments/reproduce.sh`.  Its fixed
order is:
