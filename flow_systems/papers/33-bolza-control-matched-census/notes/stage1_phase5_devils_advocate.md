## Major findings

### `P33-DA-001` — a common exact input model for both surfaces is treated as necessary when common output semantics may suffice

- **Severity:** Major.
- **Type:** Method; false-necessity risk; frame lock.
- **Exact report evidence:** The Abstract says the missing object is one exact,
  terminating, byte-stable interface applicable to both frozen
  presentations. The “Algorithmic Components and the Common-Interface
  Problem” section contrasts an algebraic-input Fuchsian route with a real-RAM
  polygon route and then requires a single interface to bind both. Findings 2
  and 5, the seven-obligation `P33-RC-1` table, and the Conclusion carry that
  common-interface premise into the fail-closed endpoint. Upstream Phase-3
  likewise names a “demonstrated common exact input model” as the missing
  executable object.
- **Finding:** Exact censuses for two different source-locked presentations do
  not obviously require one internal representation or solver. Two
  surface-specific, terminating, independently checked proof systems could
  emit the same semantic owner schema—cutoff proof, conjugacy class,
  primitivity, inversion pairing, completeness, and provenance—without sharing
  an exact input model. The report does not show why heterogeneous proof
  producers with a common verifier contract are invalid.
- **Impact:** The common-input requirement can manufacture
  `NOT_EVALUABLE_CONJUGACY_METHOD_UNAVAILABLE` even if each census is
  rigorously certifiable by a different theorem route. That weakens the claim
  that “component support without interface closure” identifies the true
  scientific bottleneck rather than one especially strict engineering choice.
