# Hénon Dynamics：路线图与交接

[P1 Wiki](../../index.md) · [方向总览](../index.md) · [首页](index.md) · [结论](conclusions.md) · [本页](roadmap.md) · [来源与阶段](sources.md)

## 原始方案：Route A 与 Route B 的分层

[研究提案](../../../henon_dynamics/propose.md) 把 Hénon 型探索组织为一条候选发现链：

```text
Hénon 映射及其推广
  → 周期轨道 / 符号结构
  → 加权动力学 zeta 或 Fredholm 行列式
  → 谱结构
  → 可能的 Hilbert–Pólya 相容性
```

这是一张**探索路线图**，不是已经完成的推导链。Route A 的职责是发现并验证候选中的结构与约束；它本身不证明 Hilbert–Pólya。Route B 只面向强 Route-A 候选，并要求独立解决自然 Hilbert 空间、算子定义/自伴性、迹公式与完成 ξ 行列式等问题。现有 Hénon 记录没有进入 Route B。

本 Session 的“低维 vs 高维”安排因此应理解为：在不同维数、系数域和模型类别中检验周期、算术与结构接口能否自然出现；不能把不同项目的局部正向结论拼接成一个未提交的全局算子。

提案还允许经典、可逆、保面积、耗散、参数族、耦合及非自治 Hénon 类。对非自治候选，单纯“模拟—时间平均矩阵—特征值拟合”会丢失轨道的时间顺序，不能充当路线闭合；至少需要可定义的自治扩张、cocycle 或 skew-product，并回到原生周期轨道、加权展开、动力学 zeta 与谱结构的同一条证据链。

## C424–C428 已执行的完整交付路径

这一批实际采用的项目路径是：

```text
精确问题筛选与独立合同准入
  → 五篇大纲及独立大纲审查
  → 真实稿件 / 初始 PDF
  → 两轮非作者稿审、裁决与必要修订
  → Route-A 正式评价及独立审查
  → 每篇两次新目录确定性构建、字节比对和逐页检查
  → 精确 payload 封存、独立成员核验
  → 精确路径 Git 提交与同步
```

这条路径的已完成状态由 [发布回执](../../../henon_dynamics/RELEASE_C424_C428.md) 记录；五项论文的论题、共享证据要求和交付门见 [C424–C428 BATCH_PLAN](../../../henon_dynamics/research_c424_c428/BATCH_PLAN.md)。封存后不应通过“整理文档”重写包内字节、历史失败记录或正式评价。

## C429–C433：从并行发现到保存检查点

下一批先以 [SCOUT_PLAN](../../../henon_dynamics/research_c429_c433/SCOUT_PLAN.md) 启动 14 条受限的数学／机制路线和 2 条跨路线综合／对抗路线（共 16 条）；后续独立核查岗位用于检查最强的存活合同，而不是把线程数当成论文数。选择门是：

```text
精确的独立问题 + 明确成功/反例判据
  → 不重复既有 C424–C428 或辅助结果的实质增量
  → 完整证明或精确反例 + 独立审查
  → 最多五项合同获准进入 C429–C433 大纲
  → 稿审、评价、构建、封存和同步的独立后续门
```

五项合同确实进入了 [C429–C433 BATCH_PLAN](../../../henon_dynamics/research_c429_c433/BATCH_PLAN.md)，但它没有替代后续门。2026-09-10 的 [会话检查点](../../../henon_dynamics/research_c429_c433/SESSION_CHECKPOINT_2026-09-10.md) 将该状态固定为“保存在途”：五项合同、零完成论文，且不把未闭合的修订、最终可复现/视觉检查或发布门认证为完成。已保存的 Route-A 记录和稿件/引文审查进度须按 [稿件协调记录](../../../henon_dynamics/research_c429_c433/MANUSCRIPT_COORDINATION.md) 的精确范围读取，不等于最终论文发布。

因此，恢复时不应从“已有编号”或“存在初稿/准备材料”直接跳到最终构建或发布。应先核对当前用户授权、当前状态、冻结输入和剩余门；历史检查点中提到的 active assignment 也不构成现在仍在执行的任务授权。

## 继续前的安全检查单

1. 读取 [Hénon AGENTS](../../../henon_dynamics/AGENTS.md)、[CURRENT_RESEARCH_STATE](../../../henon_dynamics/CURRENT_RESEARCH_STATE.md) 和 C429–C433 的 [会话检查点](../../../henon_dynamics/research_c429_c433/SESSION_CHECKPOINT_2026-09-10.md)，分开“历史进度”与“当前授权”。
2. 对 C424–C428 只读取和引用已封存材料；不要重跑、改写或把其结果拆成新合同。
3. 对一个可能的新桥，先固定对象、参数域、原生时钟、可观测量、成功/反例判据和已扣除的来源；有限枚举或漂亮的模型不自动进入合同。
4. 若开始新的正式 Route-A 评价，使用状态文件指定的当前 Route-A v0.2.0 权威及其锁定哈希；不要用本 Wiki 摘要替代评价器。
5. 保留证明、反例、失败尝试、有限计算的输入/输出与未闭合箭头。缺失目标面板应写作 `NOT_TESTABLE` / `INCOMPLETE`，不要补为 PASS 或数值零。
6. Route B、目标 Euler/根数、零点对应、投稿、外部上传和其他研究流仍需要各自的明确授权；它们不由 C 系列论文编号、封存或 Git 同步自动开启。

## 研究问题的维度对照如何复用

| 视角 | 已知项目提供的筛选价值 | 不应跨越的界线 |
| --- | --- | --- |
| 低维 / 固定模型 | C424、C425、C426、C428 提供精确分类、有限证书或模型障碍的范例，可用来检查量词、原生时钟和有限核心。 | 不能将特定系数类或静态好模型的结果外推到任意 Hénon 系统。 |
| 高维 / 跨层模型 | C427 说明高维整数递推可出现结构化半线性通道和有限余部，需要同时处理混合零边界。 | 高维的参数化不等于谱、zeta、量子化或目标算术标签。 |
| 局部—全局与有限特征 | C429–C433 把 coboundary、野周期域、测度极限、reversibility 与有限检测作为彼此不重叠的合同接口。 | 在完成、审查和发布前，它们不是可累积为最终理论的“已得五步”。 |
