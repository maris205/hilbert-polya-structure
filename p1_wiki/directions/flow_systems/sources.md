## 如何使用本页

本 wiki 是阅读入口，不替代证明、版本化项目包或正式 Route 判定。引用一个数学结论时，应优先打开具体论文、其 `paper/` 或 `stage5_finalization/` 工件以及关联的项目级 notes；引用批次状态时，应优先打开收据和完成报告。

| 需要核对的内容 | 优先来源 | 不能由它单独证明的内容 |
| --- | --- | --- |
| 定理、定义、证明范围、数值/有限计算的条件 | 具体项目论文、`manuscript.tex`、code/results/notes | 其他对象或其他项目的结论 |
| 正式 Route verdict | Route evaluator 与项目级 evaluator 输入/记录 | 仅凭 README 摘要得到的 route pass/fail |
| 研究动机、共同约束、原始阶段设计 | Session 提案与批次启动记录 | 已完成的科学执行或整体正确性 |
| 构建、内容身份、pipeline transition | Stage-4.5 / Stage-5 报告及 Stage-6 收据 | 数学正确性、投稿就绪或路线图晋级 |

## 引用和状态的最小规则

1. 把来源、推论和下一步建议分开写；一条机器审计通过不自动支持数学断言。
2. 对 P24–P28，先写清是 project result、proxy/calibrator result，还是 batch/pipeline state。
3. 任何写有 `UNASSIGNED`、`NOT_TESTABLE`、`HEURISTIC` 或 `not_checked` 的字段，应原样保留其限制，不能用邻近的正结果补全。
4. 这组链接服务于可复现阅读；若需执行新的实验、改写论文或改变 Route verdict，仍需目标项目的授权与当前合同。
