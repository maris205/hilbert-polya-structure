# Fixed seven-body adapter — SOURCE_ONLY

Only load_inputs.proposed.mjs.txt is proposed. It exports loadDecoderInputs()
and has no automatic call. Ordinary Node/fs/crypto/JSON/bootstrap and trusted
workspace ancestors are adopted; no recursive observer is introduced.

Ten compiled input paths only: the seven existing root DATA payloads and
their complete SHA256SUMS, plus stdout.canonical.json and stderr.raw at
their original fixed raw paths. The seven accepted payload SHA256 values
are literal source constants. The entire root manifest is reconstructed.
Every file gets four ten-field stat snapshots, same-fd/no-follow/regular
validation, positive-length reads through actual zero EOF, body hash and
successful close. All reads stay inside the finite allowlist, regardless
of paths in any parsed document. No directory, binding, candidate, host,
private or /proc path from DATA is opened.

The adapter checks the actual347758 request/final result and complete
native stdout RAW equality to RESULT.json. Exact accepted stdout bytes/
hash, separate empty stderr, bound-context/receipt references and complete
current closed-raw keys are checked. The already accepted V2 canonical
envelope/grammar result is reused only at that exact whole RAW pin. Neither
the V2 receiver nor the old producer is imported or rerun.

JSON parsing then extracts the eight ordered rows and lower-case body hex;
this is not ELF/cache decoding. Seven present-body hashes are recomputed
and compared against the full accepted body-pin rows. All four metadata
records/content/EOF/close fields are checked and retained. SYSTEM_PRELOAD
must be the entire exact optional ENOENT row; its empty-body digest is also
recomputed, but no absent body is passed to the decoder. Total4195947bytes
is checked, not newly inferred installed closure.

Outputs are in-memory only: seven Buffers; exact JSON manifest bytes; its
outside manifestPin; full fixed-input keys/read-count lists; and eight
body-key bindings naming exact JSON pointers into the pinned whole envelope.
The bindings preserve every original row field except redundant raw_hex,
whose body remains in the returned Buffer and original pinned envelope.
Each manifest received_key_reference uses the existing DATA_RECEPTION.md
receipt; the exact id/row-pointer mapping is explicit in authentication.
The optional absence uses that same actual accepted receipt. No new receipt
hierarchy, future receipt placeholder or path-fragment masquerading as a
physical file is needed.

manifestPin is derived outside manifestRaw, but its authority comes from
root accepting this exact projection of the previously authenticated DATA
inputs, not from computing a hash. Root must read this source and receive
the actual authentication output before using that pin as the decoder's
trustedManifestPin. This can be recorded in the actual invocation packet;
no new observer or self-hashing receipt chain is required. Failure preserves
already read fixed inputs, partial extraction and actual keys; it cannot
invoke the decoder or upgrade a missing/changed input to PASS.

After adapter source acceptance and decoder V2 source acceptance, root may
separately authorize a bounded call sequence: loadDecoderInputs(); require
the exact success status and authenticate the returned projection; then
decodeCapturedBodies(buffers,manifestRaw,outside authenticated manifestPin).
The proposal here calls neither. Exact import/command/source pins belong
to that later authorized invocation, not a guessed executable .txt launch.
