## Two different evidence types

A symlink receives lexical lstat/readlink(Buffer)/lstat only. All ten point
fields must match; returned byte length must equal the positive bounded
declared link size. Whole target bytes/hash are retained, plus reversible
UTF8 display when possible. There is no same-fd link identity, EOF/close
claim or target resolution. Non-UTF8 bytes remain exact hex, not normalized.
The primary [Node readlinkSync documentation](https://nodejs.org/api/fs.html#fsreadlinksyncpath-options)
supports returning link contents as a Buffer. The underlying
[readlink interface](https://man7.org/linux/man-pages/man2/readlink.2.html)
does not append a terminator; the complete link-size cross-check is explicit.
This is ordinary trusted API point evidence, not a hostile-race proof.

Each successful link is at most4096bytes, total12288. Node's whole-link API
does not expose a caller-set read buffer limit: if a concurrent size change
returns more, the entire actual returned Buffer is retained and the row
fails. No hard allocation/syscall/transport bound is claimed for that failure.
Negative/zero/oversize declared link size refuses before readlink. No magic
link fallback or second read is attempted.

A regular leaf follows the accepted same-fd algorithm: lstat, nofollow/
nonblock read-only open, full ten-field fstat comparison before bytes,
positive reads through actual zero EOF, after fstat/lstat, whole-size
agreement and successful close. All read counts, bytes, digest and close
errors remain. Bounds are16MiB/leaf and48MiB accepted total, plus at most
one failed overflow sentinel. The new failure row also hashes all retained
partial regular bytes; it does not label them complete. This is a new
explicit schema, not an unannounced mutation of the old reader/consumer.

Missing mandatory leaf, unsupported kind, changed key, read/open/close
error or exceeded bound stops at the first failed row. Available earlier
complete and current partial rows remain. A successful lexical link permits
continuing only to the other already listed primary leaves, never to that
link's target. After root receives the literal text, any terminal spelling
requires a separate exact selection. Neither a soname nor an apparently
familiar target proves identity with the accepted loader/tinfo bodies.
No suffix, automatic chain or fallback is selected here.
