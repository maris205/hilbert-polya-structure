This document proposes the smallest preparation needed for the first two
help/version calls. It is not a runtime acceptance and authorizes no current
probe. The amended driver/source profile and outer source must first be
received; the historical runtime packages supply mechanisms and prior

## Two separately received diagnostic entries

The optional Python and Node runtime probe sources are independent of the
driver and preload. Their only successful output says enumeration-only/root
full-key pending. Neither starts a child, invokes kpsewhich or reads manuscript
dependency bodies. Their imports are not a scientific verifier import.

Root must first receive both full probe sources and actual finite bootstrap
authority. Each future call has one literal external JSON argument with
enabled=true, status=ROOT_BOUND_RUNTIME_DISCOVERY_ONLY and two complete
source/bootstrap receipt references, in that order. Python additionally has
statx_validation_paths, a finite sorted unique literal metadata-only list
containing its own source, /dev/null and slash-root. Those paths are not
discovered recursively. No enabled probe argument is supplied in this packet.

Python's proposed interpreter is /usr/bin/python3.10 with -I -S -B and a
separate root-selected pycache_prefix that actually remains absent. Node's
probe has no startup loader/options; all six explicit builtin imports match
the preload's initial import surface. Both need exact ENV8 and physical ROOT
cwd. Root selects and binds the source/interpreter spelling, resolution,
complete byte key, full applicable configuration/loader states and exact
product request before running either entry. Actual product originals,
stdout/stderr, any yield/poll/final and absent cache state must be retained
under a separate probe capture, not the proposed contract01 output.

These probes cannot prove their own startup. If no already received finite
bootstrap mechanism can support the new ctypes/_ctypes/libffi or selected
Node import surface, root must first prepare a bounded source delta to that
mechanism and receive it. Do not launch on the theory that an after-import
map will retrospectively authorize its dependencies.

Python imports the same named modules as outer_contract.py, including ctypes,
subprocess and traceback, without importing the outer source. It records
every file-backed module pathname, whole raw self-maps, interpreter settings
and externally referenced source/bootstrap receipt originals. Path strings
are not entire runtime-file hashes. The explicitly finite metadata targets
exercise the same statx decoding and retain the actual raw 256-byte result
and fourteen integers. Root must compare these fields with an independently
received fourteen-field Node/native observation on the same unchanged
targets, with the specified atime exception, and receive the exact Linux

Unsupported libc symbols, syscall/permission/kernel/filesystem fields or
birthtime yield HOLD with no dummy fallback and no alternate ABI assumption.

The Python probe sets PR_SET_CHILD_SUBREAPER only on itself and starts no
children. It validates setter/readback and ECHILD availability, not an actual
orphan-adoption experiment or the future full supervisor lifecycle. Any
stronger runtime test requires its own explicit finite source/authority,
not a hidden test process inside this probe.

Node records every current mapped-path string, full typed builtin-source
registry fingerprint, versions, loaded-native/internal-binding list and
CommonJS cache. Root receives whole mapped executable/shared-object bytes,
aliases and loader/configuration states outside this diagnostic output.
Lazy internal bindings caused by later normal event processing or child
spawn are not all exercised by the no-spawn probe. A finite permitted list
may be source-derived from the fully received native binary/embedded source;
its provenance must explicitly say source-derived rather than observed.
Unclassified/unreceived late bindings cause the operational preload to fail.
Do not insert a wildcard, allow every string or claim the observed list
proves exhaustive OS runtime loading.

root supplies a finite descriptor universe covering:

- Every Python module/native map, including new ctypes/_ctypes/libffi; exact

  loader policy, Node version/settings, lexical/resolved names and all

must be derived from source and received complete bytes before operation.
No ldd, engine, TeX query, test build, filesystem walk or old P211 TeX840
