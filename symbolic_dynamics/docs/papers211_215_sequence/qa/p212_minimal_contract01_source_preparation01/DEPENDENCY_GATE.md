## Why the proposed graph is smaller, conditionally

The new capture source uses product calls and shell builtins, followed by
absolute env/kpsewhich exec replacement. It has no Python, ctypes, Node child,
subreaper, preload, module registry, scientific verifier or TeX build process.
Python-specific import/cache/probe rows and Node-specific probe/package-type
rows therefore have no program role in this proposed direct tool process.
The separately trusted root key/data tools are disclosed, not recursively
observed. Removing an unused interpreter does NOT prove that a library it
formerly used is absent from the new tool's independent native graph.

The current upstream kpsewhich source places help/version exits inside
command-line processing before the subsequent program-name/init_more and
lookup work. This supports a prospective help/version-only gate, not
installed binary/source equality. kpathsea_new, command parser support,
linked initializers, exit/stdio and error paths still need correspondence.
This packet does not claim their complete local closure from the upstream
file alone. [TeX Live primary source](https://raw.githubusercontent.com/TeX-Live/texlive-source/trunk/texk/kpathsea/kpsewhich.c).

The examined glibc loader uses binary path tags, environment search,
cache-selected paths and default search. Consequently a CUDA directory
can matter without GPU science if relevant resolution or preload selects
it. A saved CUDA directory identity is not evidence of that selection.
Raw ld.so.conf fragments describe configuration-production candidates;
omission from runtime input needs the actual loader/build semantics and
complete effective cache/selected-path evidence, not a name-based deletion.
[glibc 2.35 loader source](https://raw.githubusercontent.com/bminor/glibc/glibc-2.35/elf/dl-load.c).

The examined runtime linker also has preload and audit mechanisms. Clearing
the env child's variables does not make system preload or binary dynamic
tags disappear. Constructor/error/loading behavior therefore remains part
of the no-unresolved-writer and file dependency gate.
[glibc 2.35 runtime linker](https://raw.githubusercontent.com/bminor/glibc/glibc-2.35/elf/rtld.c).

The examined env implementation ultimately execs the selected program;
it does not need a Python/Node supervisor for this ordinary path. Its own
startup, locale, translated diagnostics and error branches still require
bounded source reasoning. [Coreutils 8.32 env source](https://raw.githubusercontent.com/coreutils/coreutils/v8.32/src/env.c).
Reference tags are documentary comparison choices, NOT observed installed
versions. The attempted TeX Live 2022 tag, lib.c and Bash source/manual
fetches failed and supply no positive claim; failures are retained in the
primary-source request record. No source-to-binary correspondence is inferred.

The DATA interpretation gate has an explicit finite acceptance test:

1. Read ELF fields only from the captured complete bytes: class, byte order,
   machine, PT_INTERP and every dynamic NEEDED/RPATH/RUNPATH/AUDIT/DEPAUDIT/
   INIT/INIT_ARRAY/FINI/FINI_ARRAY descriptor relevant to the selected launch.
   Validate bounds/terminated strings/table extents; reject unsupported
   executable formats, hidden/truncated tables or an unclassified loader
   mechanism. Decoder source must itself be received as DATA-only; it must
   not load, execute or resolve any string obtained from the ELF.
2. Produce a literal table with at most 32 distinct ELF image nodes, 96
   named file states and 64 initialization/finalization entries. Each edge
   records its origin body pin and byte span, literal needed/tag name,
   exact loader rule, candidate spellings and complete selected/candidate
   byte keys or actual optional-absence evidence. A returned pointer/address
   is not a proof of code behavior. Each init/fini entry is matched to a
   specific received package/source role; unsupported indirection, extra
   image/path/entry or an unresolved explicit child/load helper is HOLD.
   Do not respond to an exceeded bound with automatic recursion or a new probe.
3. For cache/default/path/hwcaps alternatives, either receive the exact
   applicable selector facts or key the complete finite possible set and
   label it a conservative set, not an observed loaded-map list. Resolve
   each needed leaf alias only under a separately named, bounded link-text
   observation; the supplied physical-leaf reader does not follow one.
   Relevant CUDA/cache path candidates are handled by the same rule.
4. For source semantics, receive an actual version/build/package record and
   the complete named app/initialization routines used in the argument,
   with exact spans and their finite configuration/locale/extra-load/child
   branches. Matching distributed binary bytes to a specific package is
   useful provenance, not a formally verified compiler theorem. A public
   upstream tag or embedded version string alone does not prove equality.
   No proof of all possible behavior of libc or of every instruction is
   claimed or demanded by this finite ordinary-trust policy.
5. The root decision must distinguish (a) directly observed complete file
   bytes/ten-field keys, (b) source-derived finite support/ordinary no-helper
   expectations, and (c) unmeasured startup, loaded-memory, hidden dynamic
   behavior and descendant limitations. The new S0 claim is discrete
   observations under that explicit ordinary behavior boundary, not strict
   source-to-binary, global constructor, full-runtime or no-writer proof.
   A concrete unresolved relevant initialization/configuration/child branch
   stays HOLD; absence of a formal whole-binary proof is recorded as a limit,
   not an invitation to inventory every compiler/runtime source.
