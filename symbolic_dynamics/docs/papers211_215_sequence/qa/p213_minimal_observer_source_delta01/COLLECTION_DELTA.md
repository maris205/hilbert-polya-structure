## F02 author remedy: owned finite diagnostics

Old failure forwarded exc.args[0] for every exact RuntimeError. New failure
never reads args or dynamic exception-class metadata. ObserverFailure is a
distinct exact type with a private owner token; its constructor and failure
handler both restrict code to the 99 literal entries in FAILURE_CODES.
Invalid internal code collapses to invalid_internal_code. Generic exceptions,
including RuntimeError and subclasses, always use operation_failed. Exact
builtin exception types receive fixed qualified labels; any other type is
other_exception. Only exact listed builtin OSError types expose an integer
errno, otherwise null. Module loader identity collection is still complete;
it is separate from exception-class diagnostic labelling.

This prevents arbitrary messages from becoming internal failure codes under
ordinary trusted in-process operation. It is not a defense against malicious
mutation of the observer's globals. The full finite code list is in source
and FINITE_FAILURE_CODES.json. Prehelper/helper/file/close/outer handling and
partial evidence remain; catastrophic output failure can still leave no
complete envelope and never licenses reconstructed evidence.
