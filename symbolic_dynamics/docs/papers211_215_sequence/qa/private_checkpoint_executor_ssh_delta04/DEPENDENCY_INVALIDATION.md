The policy necessarily removes config/provider-dependent behavior. Preserving
ordinary existing authentication availability is not the same as proving
success under the old settings, nor as forbidding arbitrary internals of a
retained agent. This task did not inspect credentials or agents to resolve
that tension. An incompatible existing requirement must be reported; it is
not permission to edit settings, enroll credentials, change destination,
contact a specialist, or extend the selected file set.

No phase binding file, binding directory, run directory, host path or live
repository was probed. The same checkpoint03 schema/path constants are kept
for protocol compatibility only; source_sha256 and the independent receipt
chain distinguish versions. An already used binding must never be overwritten
to make it fit this delta. Any namespace collision is a fresh root decision,
not author cleanup or a change to the accepted four-phase design.
