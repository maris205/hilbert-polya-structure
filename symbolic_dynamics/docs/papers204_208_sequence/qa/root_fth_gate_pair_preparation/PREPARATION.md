## Explicit observation limits

This is not an OS sandbox or complete syscall trace. Python audit hooks begin
after interpreter startup and a few standard-library imports; conservative
stdlib/config pins and module/mapping observations cover those ordinary file
dependencies, but do not prove every early open was traced. `/proc` pseudo
files and anonymous/vDSO/kernel mappings are observations, not stable inputs.
The short-lived loader subprocesses have actual ldd command/output records,
not full per-syscall traces or independently sampled maps. Bash startup files
are conservatively pinned when present; ldd runs noninteractive/non-login
with `BASH_ENV`/`ENV` absent, so that does not assert they were consumed.

Parent reads of newly produced logs/receipts are separately reported as
generated-artifact reads, not promoted to immutable pre-run inputs. Symlink
spelling, resolution and target hashes are recorded in snapshots; this is
not protection against adversarial transient filesystem races. The external
launcher shell and `env` process are outside the observed Python process;
the Python process does record and check its actual resulting environment.
Time, scheduler and OS kernel internals are not reproducible input pins.

The project research skill influences this adapter by requiring exact raw
comparison, complete original dependency preservation, and honest separation
between prepared code, new execution and archived evidence. Any actual root
result remains a finite verification receipt, not a theorem, admission,
manuscript review or batch completion.
