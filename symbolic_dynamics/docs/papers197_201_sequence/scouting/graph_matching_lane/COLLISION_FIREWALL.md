## 3. `CMM` versus `AP1`

The old `AP1` scout chooses an augmenting path of a matching uniformly and
flips it.  It was killed because Berge termination and deficiency are
classical and arbitrary graphs supplied no exact target atlas.

`CMM` uses a deterministic, state-recomputed path on one odd cycle and adds a
maximum-rank rotor branch.  Thus it is not the same transition kernel:

- `AP1` is stochastic; `CMM` is a self-map;
- `CMM` has exactly one recurrent `n`-cycle and no fixed states;
- the source path is forced by the least monomer and the next clockwise
  monomer;
- every target has the explicit triangular fibre in (3.1).

Nevertheless, augmentation, deficiency, and the size-layer census are all
zero credit.  Those facts cannot be used to argue separation.

## 4. `CMM` versus P90 Rule 184

Encoding a cycle matching by its edge word gives a cyclic binary word with no
adjacent ones.  Maximum matchings have one `00` defect.  On that shell, `CMM`
moves the defect around an alternating word, a core shape already familiar
from Rule 184.  P90 owns finite-ring traffic language, alternating recurrent
cores, sharp entry analysis, preimage enumeration, and temporal orbit/zeta
packaging.

The literal and global dynamics remain different:

- Rule 184 conserves particle number, whereas every transient `CMM` step adds
  one matching edge;
- P90 has density-resolved recurrent families, whereas `CMM` has one maximum
  rank shell and a single `n`-cycle;
- `CMM` updates one globally selected alternating arc, not all radius-one
  sites synchronously;
- `CMM`'s one-step inverse is a target-prefix interval choice with triangular
  size, not a Rule-184 space--time preimage count.

These differences establish nonidentity only.  They do not by themselves
establish sufficient residual value.

## 5. `CMM` versus the killed `GCM` domino-retile scout

`GCM` is the most serious internal proof-engine warning.  In its path-matching
encoding it greedily complements the matching on intervals left uncovered by
old edges.  A leftmost bad edge migrates right until the alternating hard-core
core is reached.  The exact package included a sharp clock, recurrent atlas,
every-target regular parser, and a Padovan exceptional fibre, but it was killed
because both time and inversion were the same one-sided traffic transducer
already occupied by P90.

The exact comparison is:

| axis | killed `GCM` | current `CMM` |
|---|---|---|
| carrier | path matchings / `2 x n` domino tilings | matchings of odd `C_n` |
| rank | matching rank is not the clock | rank increases by exactly one until maximum |
| selector | simultaneous greedy complement on every uncovered interval | one least-monomer/next-clockwise alternating arc |
| recurrent set | `2^floor(n/2)` hard-core states, paired in two-cycles | all `n` maximum matchings, one `n`-cycle |
| sharp tail | `floor((n-1)/2)` from a migrating bad edge | `m-|M|`, sharp `m` only at the empty matching |
| inverse | regular-expression parser; Padovan maximum | `T_floor(u/2)+core-indicator`; unique triangular maximum |

There is no literal equality or relabelling conjugacy: recurrent counts and
periods already forbid one.  The remaining danger is theorem-engine transfer.
Both are hard-core words entering an alternating core, and both inverse proofs
read a one-dimensional defect interval.  Therefore `CMM` is amber, not green.

## 7. Tree reserve firewall

`LGB` is not literal P114 leaf deletion, P148 even-level contraction, `TR1`
pointer doubling, `RLR` simultaneous leaf-to-root lifting, or P195 root walk:
it preserves all vertices, moves exactly one least-labelled deep leaf by one
level, has the total excess-depth clock, and has a sibling-pair inverse atlas.

However, labelled rooted-tree species, leaf allocation, rootward surgery, and
sharp path/star extrema are already heavily occupied.  The proof package is
too close to that surface to recommend beside P195 without a separate owner
and value gate.  The binding disposition is `RESERVE_ONLY`.
